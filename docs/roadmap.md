# Roadmap pagh-riscv

Шесть майлстоунов: M1 — то, что уже работает; M2–M6 — по возрастанию. Для каждого
сказано, что именно считается «сделано» (проверяемо), что есть в дереве сегодня и
что в этот майлстоун **не** входит. Майлстоун не считается закрытым, пока его
критерии не подтверждены живым запуском и не отражены в документации.

## Сводка

| # | Майлстоун | Статус | Критерий «сделано» в одну строку |
|---|---|---|---|
| M1 | Загрузка под OpenSBI, DTB, ловушки, UART-консоль и шелл | **готов** | ядро поднимается на `virt`, печатает память/timebase из DTB, шелл отвечает на команды, `halt` выключает машину |
| M2 | Физический аллокатор кадров, Sv39, куча ядра, `alloc` | почти готов: PMM + куча есть и проверены; Sv39 нет | `satp` включён, `alloc` работает, и всё это видно в логе |
| M3 | Таймер через SBI, PLIC, консоль на прерываниях | план | прерывание таймера приходит и обрабатывается, внешние прерывания разведены |
| M4 | ramfb + шрифт покрытия Fira Code, съёмка скриншотов | **готов** | экран рисует ядро, шрифт сверен с ассетом, `docs/shell.png` снимается скриптом |
| M5 | virtio-mmio блочное устройство, ext2, VFS | план | диск читается, ФС монтируется, файл доступен из шелла |
| M6 | Задачи, syscalls, Linux-compat из x86-ветки | план | планировщик переключает задачи, ELF из userland исполняется через syscall-слой |

«Готов» = критерии подтверждены живым запуском; «почти готов» = большая часть
подтверждена, остаток назван.

## M1 — загрузка, DTB, ловушки, шелл (готов)

| Критерий | Как проверяется | Подтверждение |
|---|---|---|
| `_start` паркует не-нулевые hart'ы и вызывает `kmain` | `src/arch/riscv64/boot.rs:13-38`; в логе `boot hart   0` | живой запуск |
| Стек 64 KiB, выравнивание 16 | `src/arch/riscv64/boot.rs:18-21, 44-54` | `nm`: `__stack_bottom … __stack_top` |
| DTB читается: память и timebase | `src/main.rs:65-81`, `src/fdt.rs:160-191` | `memory 0x80000000..0x90000000 (256 MiB)`, `timebase 10000000 Hz` |
| Ошибка DTB фатальна и громкая | `src/main.rs:67-71` | текст `fdt: refusing to guess the machine layout` |
| Вектор ловушек установлен | `src/main.rs:109-111`, `src/arch/riscv64/traps.rs:151-155` | кадр и диспетчер — `docs/architecture.md`, раздел 4 |
| Шелл: команды и редактор строки | `src/shell.rs:19-59, 144-230` | `.github/smoke.py`: `mem`, `hart`, `time`, `echo`, неизвестная команда, `help`, `halt` |
| `halt` действительно выключает машину | `src/shell.rs:221-227`, `src/arch/riscv64/sbi.rs:24-38` | QEMU завершается с кодом 0 (проверка в `smoke.py`) |
| Нет паники в обработчике ловушек | `src/arch/riscv64/traps.rs:4-8, 195-201` | исключение печатает `[EXC] … halting` и паркует hart |
| CI зелёный | `.github/workflows/ci.yml` | `fmt`, debug/release build, smoke в двух режимах (serial и `--ramfb`) |

Открытый хвост M1: host-тестов нет, чистая логика (`fdt.rs`) не покрыта. Для
состояния ядра тесты уже появились — это M2 (`selftest`).

## M2 — PMM, куча, `alloc`, Sv39 (почти готов)

| Критерий «сделано» | Статус | Подтверждение |
|---|---|---|
| PMM: карта физических кадров строится по DTB, а не по константе | **готово** | `src/memory/pmm.rs`; лог `pmm         62940/65536 frames free (256 MiB tracked), heap 0 KiB in 0 chunk(s)` |
| Пул не отдаёт кадры ядра, стека и DTB | **готово** | три зарезервированных диапазона (`src/main.rs:87-96`); `selftest` frames-roundtrip/frame-pattern PASS |
| Куча ядра + `alloc`: `Vec`/`String`/`Box` доступны | **готово** | `#[global_allocator]` (`src/main.rs:35-36`), `src/memory/heap.rs`; `SELFTEST heap-vec PASS` |
| Проверки не разрушают состояние | **готово** | `SELFTEST SUMMARY: 4/4 passed`, ledger `PMM hygiene: free frames 62940 -> 62940` |
| Sv39: своя таблица страниц, `satp` записан, ядро продолжает работать | **нет** | `satp` не пишется нигде; в `src/arch/riscv64/mmu.rs` лежат невызываемые примитивы Sv39; см. `docs/architecture.md`, раздел 10 |
| Ловушки page fault'ов осмысленны (не «halting» на первом же) | **нет** | ветки 13/15 в `traps.rs` печатают и останавливают hart |

Что **не** входит в M2: swap, huge pages, copy-on-write, demand paging (это придёт с
задачами в M6), NUMA, memory-mapped I/O как абстракция.

Осторожно при стыковке с M4 и M5: DMA-путь `fw_cfg` передаёт **физический** адрес
(предупреждение в шапке `src/drivers/fw_cfg.rs`). Как только Sv39 встанет между
ядром и RAM, эти строки придётся превратить в трансляцию — иначе ramfb и virtio
получат мусор.

## M3 — таймер через SBI, PLIC, консоль на прерываниях (план)

| Критерий «сделано» | Как будет проверяться |
|---|---|
| Таймер программируется через SBI TIME (не через `mtimecmp` — он M-mode) | тики растут без опроса; `time` и задержки работают |
| `sie` включает нужные источники, `stvec` их обрабатывает | ветка `CAUSE_SUPERVISOR_TIMER` перестаёт быть пустым `return` |
| PLIC разведён: внешние прерывания доходят | ветка `CAUSE_SUPERVISOR_EXTERNAL` печатает устройство, а не «not routed yet» |
| Консоль не теряет байты при прерываниях | ввод не зависит от polling'а; smoke-тест проходит |
| Критические секции маскируют прерывания | `uart::put_byte` под `without_interrupts` |

Обязательное условие, а не пожелание: **до** включения любого `sie`-бита
критическая секция UART должна маскировать прерывания. Сегодня `uart::put_byte`
берёт спинлок с включёнными прерываниями (`src/drivers/uart.rs:67-73`), а
`sync.rs:4-8` описывает инвариант, который никем не обеспечен; обработчик внешнего
прерывания печатает в консоль (`src/arch/riscv64/traps.rs:178`), то есть встанет на
локе, удерживаемом прерванным контекстом. Разбор — `docs/architecture.md`,
раздел 10.1. Не входит в M3: SMP-таймеры, tickless, watchdog, per-hart прерывания.

## M4 — ramfb, шрифт покрытия, скриншоты (готов)

| Критерий | Подтверждение |
|---|---|
| `fw_cfg` читает `etc/ramfb`, ядро настраивает framebuffer | лог `framebuffer  ramfb 1280x800 stride 5120 cells 100x37` |
| Консоль блитит шрифт покрытия, а не «кирпичи» | `tools/font_check.py --scan-all`: 6880 клеток, ни одна не содержит пикселей вне `assets/font8x18.bin` |
| Скриншот снимается скриптом воспроизводимо | `python3 tools/run.py --keys "help\n" --shot docs/shell.png --check-font --scan-all` → exit 0 |
| Верх README показывает реальный экран | `docs/shell.png` в репозитории, снят из работающего QEMU |
| Путь экрана под CI | `.github/smoke.py --ramfb` (без дисплея) |

Известный хвост M4 (вне зоны правки подсистемы): `run.sh` не передаёт
`-device ramfb`, поэтому «из коробки» лаунчер показывает только serial; README
описывает флаг явно. Не входит в M4: GPU-ускорение, смена разрешений «на лету»,
TTF-парсер (только офлайн-растетризованный ассет), окна и прикладная графика.

## M5 — virtio-mmio, ext2, VFS (план)

| Критерий «сделано» | Как будет проверяться |
|---|---|
| virtio-mmio блочное устройство найдено по DTB и читает секторы | чтение сектора в логе, данные совпадают с образом |
| ext2 монтируется, файл читается | `ls`/`cat` из шелла |
| VFS-слой отделяет ФС от шелла | дерево модулей + README подсистемы |
| Диск не портится: запись либо есть, либо её нет | явное решение и тест на образе |

Не входит: журнал (WAL из x86), другие ФС, hot-plug, разделы, кэш страниц.

## M6 — задачи, syscalls, Linux-compat (план)

| Критерий «сделано» | Как будет проверяться |
|---|---|
| Планировщик переключает задачи (сначала ядровые) | две задачи печатают по очереди |
| Переключение контекста сохраняет кадр корректно | тот же контракт смещений, что в `traps.rs`, плюс тест |
| Syscall-интерфейс и U-mode | приложение из ELF работает |
| Linux-compat слой из x86-ветки портирован на RISC-V ABI | статический Linux/RISC-V ELF запускается |

Зависит от M2 (адресные пространства, Sv39) и M3 (таймер). Не входит: сеть, apt,
пакеты — они есть в x86-репозитории, но в RISC-V-репозитории не планируются (см.
«Вне области»).

## Вне области (сознательно)

| Что | Почему |
|---|---|
| SMP | `_start` паркует все hart'ы кроме нулевого (`boot.rs:14-16`), все структуры ядра рассчитаны на один контекст, `sync.rs` — один нереентерабельный спинлок. SMP — это другой boot-протокол, per-hart стеки и настоящие локи; до M6 не планируется |
| Реальное железо | адреса UART и `fw_cfg` захардкожены (`uart.rs:20`, `fw_cfg.rs`), `-kernel` + OpenSBI — единственный поддерживаемый путь загрузки. Цель — QEMU `virt` |
| RV32, другие ISA, H-расширение (виртуализация) | ядро RV64-only; `riscv64gc-unknown-none-elf` — единственный таргет (`.cargo/config.toml:2`) |
| Свой загрузчик, UEFI-цепочка, ISO | x86-репозиторий грузится через Limine; здесь загрузчик — OpenSBI, и менять это незачем |
| Модель безопасности | до M6 нет U-mode и адресных пространств, после — тоже без обещаний: это учебное ядро |
| Сеть, apt, пакеты, TLS | есть в [ccclosed/Pagh-OS](https://github.com/ccclosed/Pagh-OS); в этот репозиторий не портируются |
| Windows-лаунчер (`run.cmd`-аналог) | `run.sh` — канонический путь; legacy-парность, как в x86, не поддерживается |
| Внешние крейты | `Cargo.toml:8-9` пуст; зависимость — архитектурное решение, а не деталь реализации |

## Как закрывается майлстоун

1. Критерии из таблицы подтверждены живым запуском (серийный лог), а не чтением
   кода.
2. `.github/smoke.py` расширен маркерами новой подсистемы; для состояния —
   in-QEMU selftest (как `selftest` в M2), для чистой логики — host-тесты, когда
   они появятся. Иначе регрессию поймает человек, а не CI.
3. Обновлены `README.md` («что работает сегодня»), `docs/architecture.md` и
   README подсистемы; статус в этой таблице переставлен.
4. Гейты CI зелёные (см. `AGENTS.md`), версия в `Cargo.toml` + `Cargo.lock`
   поднята, если поведение видимо снаружи.
