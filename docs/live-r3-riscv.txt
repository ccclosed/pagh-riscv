#   sha256 7b6cec8f720029e50b96c394cf1594bc911a65c189f8e80532c8f58c77931d21
# stock baseline:   0.24.2 debug kernel built at HEAD 7f0287c
#   sha256 fbc761e10c1b4e05c5df301c13e8a47f6229819f31921a5ab3ee907de6ab0ca5   (the round-3 report's fbc761e1… build)
# rig: a copy of attack/r3/riscv at /tmp/pagh-r3/riscv-stand (QEMU virt +
#   OpenSBI, 64 MiB host mke2fs ext2 base.img, serial shell). The copy adds a
#   boot proof the round-3 rig did not have: `cat /proc/version` is sent as the
#   first shell command and run.sh greps the expected line out of the serial
#   log, so a log below cannot come from the other kernel by accident.
# PoCs:
#   attack/r3/riscv/poc/dirent_bomb.elf  — 1200 U-mode creates then openat(/mnt)
#   attack/r3/riscv/poc/sigframe_link.rs — forged SignalFrame.prev_frame
#   /tmp/pagh-r3/riscv-stand/poc/sigframe_link_fixed.rs — same forgery, but the
#     handler asks rt_sigreturn for its answer, records the errno, repairs the
#     word and unwinds normally. The original PoC only leaves the forged value
#     installed, so on a fixed kernel its handler would spin after -EINVAL and
#     never print the result; this variant makes the -EINVAL observable.
# Reproduction (paths are the throwaway stand copy):
#   cd /tmp/pagh-r3/riscv-stand
#   PAGH_BIOS=/usr/share/qemu/opensbi-riscv64-generic-fw_dynamic.bin \
#       ./run.sh poc/dirent_bomb.elf
#   ... BASE=img/hostile.img CMD='ls /mnt' ./run.sh
#   ... ./run.sh poc/sigframe_link_fixed.elf
#   stock: KERNEL=/tmp/pagh-r3/pagh-0.24.2-debug.elf \
#       BOOT_PROOF='pagh 0.24.2 (riscv64) #1' ./run.sh ...
#
# Fixed checks (all exit 0, clean `halt: powering off`):
#   F-r3-rv-2 U-mode: 1200 creates, openat("/mnt") = -E2BIG (-7), shell alive.
#   F-r3-rv-2 image:  `ls /mnt` on the 1100-dirent hostile.img prints
#                     "ls: /mnt: directory listing too big", no panic.
#   F-r3-rv-1:        both forged rt_sigreturn calls answer -EINVAL (-22); the
#                     frame stays armed, the handler repairs it and unwinds,
#                     the program exits 0 with the hart alive.
# Stock baseline (exit 1 / parked hart, expected):
#   F-r3-rv-2 U-mode: [PANIC] memory allocation of 65536 bytes failed.
#   F-r3-rv-2 image:  the same panic from the shell's own `ls /mnt`.
#   F-r3-rv-1:        1st sigreturn accepts usize::MAX (handler never returns,
#                     main prints 0); the 2nd delivery panics in arm():
#                     "attempt to add with overflow" at src/user/signal.rs:1470.
# Each section below starts where the evidence starts: the three fixed runs keep
# the guest serial from the kernel banner (the OpenSBI preamble is elided), the
# three stock sections keep the two shell commands and the panic; the text in
# between is verbatim serial output.
