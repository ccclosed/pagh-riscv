# `src/arch/` — архитектурный слой

Один каталог на архитектуру; сегодня ровно одна — RV64. Смысл слоя: подсистема
(шелл, консоль, память) спрашивает факт о машине **здесь**, а не лезет в регистр
сама (`src/arch/mod.rs:1-7`).

| Файл | Владеет | Не должен |
|---|---|---|
| `riscv64/boot.rs` | `_start`: стек, парковка hart'ов, захват hart id, вызов `kmain` | вызывать что-либо, кроме `kmain` |
| `riscv64/csr.rs` | типизированные чтение/запись CSR, `without_interrupts` | содержать логику: каждый хелпер — одна инструкция |
| `riscv64/sbi.rs` | `ecall` в M-mode (сегодня — SRST shutdown) | трогать M-mode CSR напрямую |
| `riscv64/traps.rs` | `stvec`, `trap_entry` (в т.ч. U-mode вход/возврат через `sscratch`), кадр ловушки, диспетчер | паниковать; возвращаться после S-mode исключения |
| `mod.rs` | факты о машине: `hart_id()`, `park_forever()` | зависеть от подсистем выше |

## Контракты

**Кадр ловушки — это ABI.** `trap_entry` (`riscv64/traps.rs:57-140`) сохраняет
31 регистр (`ra`, `sp`, `gp`, `tp`, `t0–t6`, `s0–s11`, `a0–a7`) и два CSR
(`sepc`, `sstatus`) в фиксированном порядке; `#[repr(C)] TrapFrame`
(`riscv64/traps.rs:20-55`) объявляет поля в том же порядке. Размер кадра — 264
байта (`addi sp, sp, -264` в начале, `addi sp, sp, 264` в эпилоге). Смещения
0…256 сведены в таблицу в `../../docs/architecture.md` (раздел 4.1) — при
добавлении поля её нужно обновить вместе с ассемблером.

Слот 8 (`sp`) имеет **двойной смысл**, и это ABI, а не деталь реализации:
для ловушки из S-mode он хранит базу самого кадра (сначала `sp` уменьшается на
264, потом сохраняется), а для ловушки из U-mode — прерванный **user `sp`**
(он нужен, чтобы вернуть U-mode в свою же точку). Поэтому `trap_entry` сначала
обменивается `sp` с `sscratch`, решает по ненулевому значению, откуда пришла
ловушка, и только потом строит кадр. В эпилоге путь S-mode восстанавливает `sp`
арифметикой, путь U-mode — загрузкой из слота 8. Следствие: `[EXC] … sp=…`
печатает адрес кадра для S-mode и user `sp` для U-mode.

**Прерывания возвращаются; исключения — либо убивают задачу, либо паркуют
hart.** `sepc`/`sstatus` восстанавливаются из кадра, затем `sret` — это общий
эпилог, но путь возврата различается по **сохранённому** `sstatus.SPP`:
S-mode — арифметика старого эпилога; U-mode — заново вооружить `sscratch`
(база кадра + 264) и загрузить user `sp` из слота 8. Диспетчер различает
прерывание по биту 63 `scause` (таймер → `timer::on_tick`, внешнее → PLIC).
Синхронное исключение с `SPP == 0` — это U-mode: `ecall` (cause 8) уходит в
`user::syscall::dispatch`, всё остальное — в `user::on_fault`, который печатает
одну строку и завершает **задачу**, а не машину. Исключение из S-mode
по-прежнему печатает имя, `scause`/`stval`/`sepc`/`ra`/`sp` и паркует hart:
продолжить безопасно нельзя.

**CSR — только супервизорные.** Используются `stvec`, `sepc`, `scause`, `stval`,
`sstatus`, `time`, `sie`/`sip` (таймер + внешние), `sscratch` (U-mode контракт,
см. ниже) и `satp` (через `memory::paging`). `sstatus.SIE` включается в
`traps::init`, но прерывание приходит только от источников, которые явно
разрешены после своей инициализации: `sie.STIE` — после `set_timer`,
`sie.SEIE` — после `plic::init` и `uart::enable_rx_interrupt()`. Порядок —
часть контракта, обратный теряет байт или ловит прерывание по неготовому
регистру.

**U-mode: вход, `sscratch` и возврат (M6b).** Пока выполняется S-mode,
`sscratch == 0`; `traps::init` явно обнуляет его. Перед входом в U-mode
`user::enter_user` собирает `sstatus` (SIE=0, SPP=0, SPIE=1, SUM=0), пишет
`sscratch = sp` (стек ядра задачи — куда придёт первая ловушка), `sepc = entry`
и делает `sret`. `trap_entry` начинается с `csrrw sp, sscratch, sp`: ненулевой
`sp` = «пришли из U-mode», user `sp` сохраняется в слот 8, а `sscratch`
обнуляется; ноль = обычная S-mode ловушка. Эпилог по сохранённому `SPP`
выбирает путь и для U-mode возвращает `sscratch` в значение «стек ядра»,
поэтому каждая следующая ловушка снова находит безопасный стек. Правила:
`sscratch` не читать/писать вне `traps.rs`/`user/mod.rs`; `sret` в U-mode ровно
один (`enter_user`); `ecall` возвращается на `sepc + 4` (это делает
`user::syscall::dispatch`).

**M-mode недоступен.** `mhartid` — M-mode CSR: `csrr …, mhartid` из S-mode это
illegal instruction (`scause = 2`), и это не теория — старая реализация команды
`hart` убивала машину. Id захватывается в `_start`, пока он в `a0`
(`riscv64/boot.rs:23-28`), в статик `BOOT_HART_ID` (`:56-63`), а `hart_id()`
(`mod.rs:23-33`) читает его. Единственная дверь в M-mode — `ecall`.

**Один hart.** `bnez a0, 2f` (`riscv64/boot.rs:16`) отправляет все hart'ы кроме
нулевого в `wfi`-цикл (`:33-38`) до любого Rust-кода. SMP — это другой
boot-протокол, а не правка одной ветки.

## Чего нет

IPI, SMP, per-hart состояния, гипервизорных расширений, отдельных страничных
таблиц на процесс (`satp` один; U-бит в общей карте), обработки S-mode
page fault (такой сбой, как и раньше, печатается и паркует hart). U-mode,
syscall'ы, ELF и таймер-in-U уже есть — M6b; см. [`../user/README.md`](../user/README.md)
и `../../docs/roadmap.md`.

Стиль файлов: комментарий объясняет контракт и «почему так», каждая
`unsafe`-вставка — с `SAFETY:`; ассемблерные блоки — `global_asm!` рядом с
Rust-структурой, которую они обязаны повторять.
