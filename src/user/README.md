# `src/user/` — user mode, syscalls и ELF (M6b)

M6b — первое место, где код исполняется с U-битом в PTE: `sret` в U-mode,
`ecall`-диспетчер, ELF64-загрузчик и маленькие статические программы из
[`userland/`](../../userland/README.md). Модуль намеренно не строит отдельное
адресное пространство: user-страницы кладутся в **ту же** Sv39-карту ядра, но с
`U=1`.

## Карта

| Файл | Роль |
|---|---|
| `mod.rs` | `run_image(bytes, name)` — весь сценарий запуска: ELF → user-стек → `spawn` задачи → `enter_user` (`sret`) → ожидание `Exited` → `reap` → снятие маппингов; `Exit`/`UserError`, `on_fault`, `RUN` (одна программа за раз), встроенные фикстуры `HELLO_ELF`/`FAULT_ELF`/`SPIN_ELF` |
| `elf.rs` | ELF64-загрузчик: валидация заголовка/program headers/сегментов **до** первого кадра, `PT_LOAD`-страницы `U=1` в общей карте, копирование, нулевой `.bss`-хвост, откат кадров при любой ошибке; `Loaded { entry, pages(), release() }`, типизированный `ElfError` |
| `syscall.rs` | `dispatch(frame)`: Linux/RISC-V номера `write(64)`, `exit(93)`, `sched_yield(124)`, `getpid(172)`; проверка user-указателей, `SUM` только вокруг копии, `ecall → sepc + 4`, счётчики для selftest |
| `selftest.rs` | семь проверок для `selftest`: accept фикстуры, reject-матрица (14 мутаций заголовка/сегментов), отказ `run_image` на битом ELF, round-trip `hello`, fault-изоляция, запуск после fault, таймер-in-U |

## Раскладка адресов

```text
0x0000_0000 … 0x0000_ffff   не отображено (включая 0 — на этом стоит fault-фикстура)
0x0001_0000 … 0x3fff_0000   окно образа: PT_LOAD-страницы с U=1 (≤ 256 страниц)
0x3fff_0000 … 0x4000_0000   user-стек: 64 KiB = 16 кадров, U=1
0x4000_0000                 stack_top — начальный sp программы
0x8000_0000 …               RAM ядра: identity-карта, страницы без U
```

Окно ниже RAM, но численно пересекается с PLIC (`0x0c00_0000`) и UART
(`0x1000_0000`) в карте ядра: ELF, который просит эти адреса, получает
`ElfError::AddressInUse` от page-table walk, а не «почти работает».

## Контракты (инварианты M6b)

1. **Одно адресное пространство, один ASID.** User-страница отличается только
   битом `U`; второго `satp` нет, `satp` не переключается при входе в U-mode.
   Два user-процесса друг от друга не защищены; `RUN` держит «одна программа за
   раз» и второй параллельный запуск получает `UserError::Busy`.
2. **Вход в U-mode — единственный `sret` в U.** `enter_user` собирает `sstatus` в
   Rust (`SIE=0, SPP=0, SPIE=1, SUM=0`) и пишет его `csrw sstatus`, затем
   `sscratch = sp` (стек ядра для первой ловушки), `sepc = entry`,
   `sp = stack_top`, `sret`. Биты SPIE (5) и SPP (8) не влезают в 5-битный
   immediate `csrsi`/`csrci` — не пытаться ставить их «как раньше».
3. **`sscratch` — часть контракта ловушки.** Пока выполняется S-mode,
   `sscratch == 0`; перед входом в U-mode туда кладётся `sp` ядра. `trap_entry`
   первым делом делает `csrrw sp, sscratch, sp`: ненулевой `sp` = ловушка из
   U-mode (user `sp` сохраняется в слот 8 кадра), ноль = ловушка из S-mode.
   Эпилог различает пути по **сохранённому** `sstatus.SPP` и для U-пути заново
   вооружает `sscratch` (база кадра + 264) до восстановления user `sp`.
4. **Слот 8 кадра имеет двойной смысл:** S-mode — база кадра, U-mode — прерванный
   user `sp`. Ассемблер, `TrapFrame` и `docs/architecture.md` §4.1 меняются одним
   коммитом.
5. **`ecall` возвращается на `sepc + 4`.** `dispatch` обязан сдвинуть `sepc`:
   `sret` возвращается в `sepc`, а `ecall` — 4-байтная инструкция; без сдвига
   программа бесконечно повторяет системный вызов.
6. **User-указатели не доверяются.** `write` проверяет каждую страницу диапазона
   по PTE (`U=1` и `R=1`) **до** копии; `SUM` включается вокруг
   `copy_nonoverlapping` и восстанавливается из точного прежнего значения.
   Адрес ядра, дырка или guard-страница → `-EFAULT`, а не page fault.
7. **Fault из U-mode убивает задачу, не машину.** Исключение с сохранённым
   `sstatus.SPP == 0` (кроме `ecall`) уходит в `on_fault`: одна строка
   `[user] <name> killed: …` и `scheduler::exit`; раннер освобождает страницы и
   стек. Исключение из S-mode по-прежнему печатает и паркует hart.
8. **`RUN` не держится через блокирующее ожидание.** Лок берётся на захват,
   короткие обновления и снятие; `wait_for_exit` крутит `yield_now` без него;
   teardown делает раннер (trap-пути только читают/пишут запись).

## Жизненный цикл `run_image`

1. захват `RUN` (`Busy`, если занято);
2. `elf::load`: валидация → маппинг страниц (при ошибке — откат и `Err`);
3. 16 кадров contiguous под user-стек + маппинг `U|R|W`;
4. `task::spawn(user_task)`; шелл ждёт `Exited` в цикле `yield_now`
   (таймер продолжает вытеснять, пока ждём);
5. `scheduler::reap` (стек задачи), `unmap` стека, `Loaded::release`, снятие `RUN`;
6. `Ok(Exit)` — `Code(n)` для `exit(2)` или `Fault { reason, cause, sepc }`.

## Пределы (честно)

- образ ≤ 1 MiB / 256 страниц / 8 `PT_LOAD` / 8 program headers (`elf.rs`);
- `run <path>` читает файл в **один** heap-буфер (`try_reserve`), т.е. не больше
  одного 64 KiB-чанка; образ крупнее отвергается строкой, а не паникой
  (встроенные фикстуры этим лимитом не ограничены — они в `.rodata` ядра);
- нет per-process page table/ASID (изоляция только «юзер vs ядро»), нет
  `brk`/`mmap`, динамического ELF, `fork`/`exec`, сигналов, нескольких процессов;
- U-mode не имеет доступа к устройствам (их страницы без `U`) и не может
  выполнять привилегированные инструкции — это обеспечивает железо, а не код.

## Как проверяется

```text
run demo     # hello: write + sched_yield + exit 42
run fault    # getpid, затем load с адреса 0 -> killed: load page fault; машина жива
run spin     # 0.2 s в U-mode (~20 timer interrupts из U), getpid, exit 7
selftest     # SELFTEST user-*: 7/7, PMM-ledger до/после одинаковый
```

Два `selftest` подряд печатают одинаковые ledger'ы — это и есть доказательство,
что не течёт ни образ, ни стек, ни стек задачи. Таймер-in-U проверяется счётчиком
`traps::user_timer_ticks()` (инкремент только при `SPP == 0`). Скриншот —
`docs/user.png`, снимается `tools/run.py` (см. `docs/screenshot.md`).
