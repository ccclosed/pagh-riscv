# `src/pkg/` — нативный установщик пакетов

`pkg` ставит в `/mnt` один статический RV64 ELF из файла `.ppkg`, скачанного
по **plain HTTP** с плоского репозитория. Это не apt: нет Debian-метаданных,
`.deb`, solver'а зависимостей, сжатия, OpenPGP и TLS. Проверка, которая есть, —
размер и SHA-256 из индекса. Это целостность скачанного файла, а не
аутентификация источника: зеркало, которое врёт, этим дизайном не ловится, и
документация не должна называть это подписью.

## Карта

| Файл | Роль |
|---|---|
| `mod.rs` | состояние (`repo`, кэш индекса), HTTP-клиент поверх `net::tcp`, разбор индекса и манифеста, установка/удаление, команды шелла |
| `sha256.rs` | потоковый SHA-256 (FIPS 180-4), без аллокаций и зависимостей; `selftest()` — known-answer проверка для `pkg selftest` |

Формат пакета и индекса — `pagh-programs/docs/package-format.md`; здесь только
то, как ядро его исполняет.

## Конвейер установки

1. **`/mnt` обязателен.** `mount_node()` ищет смонтированный каталог; без него
   `install`/`remove`/`list`/`installed` печатают ровно
   `pkg: /mnt is not mounted` и ничего не трогают.
2. **Индекс.** `pkg index` делает `GET <repo>/index`, требует статус `200`,
   пропускает заголовки и разбирает тело **построчно**. Строка длиннее 256
   байт, чужой header или не-`200` — ошибка, а не частичный кэш: кэш очищается
   до запроса и заполняется только после успешного разбора.
3. **Поиск.** `pkg install <name>` берёт запись из кэша; без `pkg index` —
   `no index cached (run 'pkg index')`.
4. **Скачивание + хеш.** Тело `GET <repo>/<url>` пишется в
   `/mnt/pkg/<name>.ppkg` кусками по 4 KiB; те же байты идут в `Sha256`.
   Счётчик не может превысить `size` из индекса (иначе загрузка обрывается),
   после EOF он обязан с ней совпасть, а hex-дайджест — с `sha256`.
5. **Шлюз.** Пока размер и SHA-256 не совпали, в `/mnt/bin` не создаётся
   ничего, а скачанный файл удаляется. `install` возвращает ошибку одной
   строкой — паники на сетевом/пакетном пути нет.
6. **Разбор.** Только после шлюза читаются `PPKG0001`, `u32 manifest_len`,
   `u32 payload_len` (LE) и манифест. `16 + manifest_len + payload_len` должен
   совпасть с размером из индекса, `manifest_len ≤ 2 KiB`,
   `payload_len ≤ 8 MiB`; `name` манифеста обязан совпасть с запрошенным.
7. **Распаковка.** `kind=app` — payload потоково копируется в
   `/mnt/bin/<name>`; `kind=applet-bundle` — в `/mnt/bin/paghbox`, затем по
   симлинку на каждую команду из `commands` (цель `paghbox`).
8. **Манифест последним.** Нормализованный `name/version/kind/commands`
   пишется в `/mnt/pkg/<name>.manifest`. Пакет с манифестом — пакет, дошедший
   до последнего шага; `pkg remove` читает только его.

При любой ошибке после создания цели в `/mnt/bin` цель (и симлинки bundle'а)
удаляется, а `.ppkg` — тоже; частично установленного пакета не остаётся.
Успешная установка печатает ровно `pkg: installed <name> <version>`.

## Удаление и список

* `pkg remove <name>` читает `/mnt/pkg/<name>.manifest`, удаляет
  `/mnt/bin/<name>` (или симлинки команд и `paghbox`), затем `.ppkg` (если он
  есть) и **последним** манифест. Отсутствующий файл — не ошибка; нет
  манифеста — `is not installed`.
* `pkg installed` перебирает `/mnt/pkg/*.manifest`, печатает по строке
  `pkg: <name> <version>` и итог `pkg: N package(s) installed`.
* `pkg list` печатает записи индекса и `[installed]` для тех, у кого есть
  `/mnt/pkg/<name>.manifest`.

## Память и пределы

Ни одного буфера размером с пакет или индекс:

* репозиторий — фиксированные 160 байт (`Repo`), не `String`;
* индекс — 64 записи фиксированного размера (`name[32]`, `version[16]`,
  `sha[65]`, `size`, `url[96]`) в статике; строки парсятся по мере прихода;
* манифест — 2 KiB на стеке, хранимый манифест — 512 байт;
* payload копируется кусками 4 KiB из уже проверенного `.ppkg`; кучи под него
  нет.

Пределы MVP: 64 пакета в индексе (лишние строки игнорируются), IPv4-хост в
`repo` (DNS в установщике не используется, хотя резолвер в ядре есть), порт по
умолчанию 80, payload ≤ 8 MiB, только схемы `http://`. `pkg repo` проверяет URL
сразу и отказывает `https://` строкой «only plain http:// is supported (there
is no TLS yet)».

## Зависимость от TCP

Пакет `hello` — 13.5 КиБ, а не один сегмент. На этом размере выяснилось, что
TCP-клиент (`src/net/tcp.rs`) объявлял окно 4096 независимо от занятости
буфера, из-за чего лишние байты терялись и восстановление ждало RTO; повторное
соединение с тем же локальным портом (49152) после закрытия молча теряло SYN в
user-network QEMU. Оба дефекта исправлены в `net`: окно = свободное место,
window update после `recv`, duplicate ACK на разрыв, свежий локальный порт на
соединение, 10 с на шаг данных. Без этого установка 13 КиБ была флаки.

## Проверка

```sh
python3 tools/test_pkg.py            # сборка .ppkg, HTTP-сервер, QEMU с диском
python3 tools/test_pkg.py --release
```

Харнесс проверяет положительный путь (index → install → `ls /mnt/bin` →
`run /mnt/bin/hello` → `hello from user mode` + код 42 → installed → remove) и
отрицательный: один байт хостовой копии пакета перевёрнут при том же индексе —
установка обязана отказать по SHA-256, а `/mnt/bin/hello` и `.ppkg` не должны
появиться. Логи (`serial.log`, `http.log`, `network.pcap`) остаются в
напечатанном временном каталоге.

В самой QEMU-сессии доступна ещё одна проверка:

```
pkg selftest        # pkg: sha256 selftest ok — те же FIPS-векторы, что в cfg(test)
```

`cfg(test)`-модуль в `sha256.rs` собирается только host-тестом (крейт —
bare-metal образ и libtest не линкует), поэтому рантайм-помощник повторяет
empty/`abc` прямо в гостевом ядре.
