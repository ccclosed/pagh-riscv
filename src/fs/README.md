# `src/fs/` — ext2 и политика форматирования

Файловая система M5: ext2 на блочном устройстве из `drivers::block`, порт
x86-версии (`Pagh-OS/src/fs/ext2/`) без журнала и с тремя осознанными
изменениями. Каталог документирует себя сам; здесь — устройство, инварианты и
то, чего нет.

## Карта

| Файл | Роль |
|---|---|
| `mod.rs` | фасад: `FsError`, `init_fs`-контракт (формат только пустого устройства) |
| `ext2/mod.rs` | mount, чтение/запись файлов, каталоги, rename, truncate, формат (mkfs) |
| `ext2/structs.rs` | on-disk структуры (`Ext2SuperBlock`, `Ext2GroupDesc`, `Ext2Inode`, dirent) с `const`-проверками смещений |
| `ext2/inode.rs` | чтение/запись inode, таблица inode по группам |
| `ext2/dir.rs` | dirent-цепочка: перебор, вставка, удаление |
| `ext2/alloc.rs` | битмапы блоков и inode, счётчики групп |
| `ext2/symlink.rs` | быстрые и обычные символические ссылки |
| `format_policy.rs` | **единственное решение, которое может стереть данные**: пусто ли устройство? |
| `selftest.rs` | неразрушающие проверки для команды `selftest` (RAM-устройство) |

## Что важно знать

* **Форматирует только пустое.** `main.rs::init_fs` сначала пытается смонтировать
  устройство; формат спрашивается только после неудачного монтирования и только
  через `format_policy`: нулевые байты — формат, MBR/GPT или чужие данные —
  отказ с названием причины. Разметка/чужие данные не стираются никогда.
* **Блочный размер динамический.** `format` выбирает 4096 Б для устройств ≥ 32 KiB
  и 1024 Б ниже; при монтировании геометрия (`block_size`, `inode_size`,
  `ptrs_per_block`, `s_first_data_block`) читается из суперблока и передаётся во
  все расчёты. Поэтому образ, сделанный хостом (`mkfs.ext2 -t ext2`), монтируется
  как есть.
* **Порядок записи.** Данные пишутся раньше метаданных (`Tx`), поэтому
  зафиксированные метаданные никогда не ссылаются на незаписанный блок. Журнала
  нет: сбой между двумя записями может оставить операцию недоделанной — это
  названо в `docs/roadmap.md` (журнал — вне M5).
* **Всё тотально.** Повреждённые значения с диска превращаются в `FsError`, а не
  в панику; каждый 32-битный индекс проверяется до использования. Директория с
  битым `rec_len` даёт `Corrupt`/`IoError`, а не уход за границу буфера.
* **`rename` — настоящая операция**, а не copy+unlink: перепривязка inode в одной
  транзакции, с отказом переносить директорию внутрь собственного поддерева.
* **Пределы:** нет журнала/WAL, нет квот, прав/uid/gid, разреженных файлов,
  больших файлов (двойной indirect есть, тройного нет), нет роста числа групп
  сверх `MAX_GROUPS` (формат откажет), нет sudo/аттрибутов и ACL.

## Формат на диске (то, что пишет `format`)

* блок 1 (байт 1024) — суперблок: `s_magic = 0xEF53`, `s_log_block_size`,
  счётчики блоков/inode, `s_first_data_block`, размер inode;
* дальше таблица дескрипторов групп (`Ext2GroupDesc`) — по одной записи на
  группу, каждая указывает битмапы и таблицу inode;
* корень — inode 2 (`.` и `..`), `lost+found` — inode 11;
* `s_state = CLEAN`, никаких journal-полей.

## Как проверить

```sh
cargo build                                                        # ядро
# пустой диск: ядро само форматирует и монтирует
qemu-img create -f raw /tmp/fs.img 64M
python3 /tmp/riscv_drive.py --kernel target/riscv64gc-unknown-none-elf/debug/pagh \
    --keys "ls /mnt" --keys "write /mnt/a.txt hi" --keys "cat /mnt/a.txt" \
    --expect lost+found --expect hi --disk /tmp/fs.img \
    --qemu-extra "-global virtio-mmio.force-legacy=false"
# повторная загрузка того же образа: монтирование без формата, файл на месте
python3 /tmp/riscv_drive.py ... --keys "cat /mnt/a.txt" --disk /tmp/fs.img ...
# совместимость с хостовым mkfs.ext2: файл, записанный debugfs, читается
mkfs.ext2 -q -t ext2 -F -b 4096 /tmp/host.img
debugfs -w -R "write /tmp/file.txt host.txt" /tmp/host.img
python3 /tmp/riscv_drive.py ... --keys "cat /mnt/host.txt" --disk /tmp/host.img ...
e2fsck -fn /tmp/host.img                                          # чисто после загрузки
```

Внутри гостя: `selftest` печатает `SELFTEST ext2-* PASS/FAIL` (11 проверок:
формат, запись/чтение, каталоги, truncate, symlink, rename, remount, счётчики,
испорченный ввод, политика формата, read-only проверка реального диска) и
`SELFTEST ext2 summary: n/n passed`; два прогона в одной загрузке обязаны дать
один и тот же `PMM hygiene` ledger.
